# NBA150 完整讨论版实验条件

本目录生成 NBA150 溯因任务的七个讨论版条件，每个条件 150 题。任务始终是结合目标位置之前和之后可见的证据，判断缺失位置发生了什么，不是预测下一事件。本次只生成和验证本地文件，没有调用 GLM 或其他模型 API，没有运行评测，也没有虚构准确率或诊断结果。

## 文件

- `build_conditions.py`：仅依赖 Python 标准库的生成与验证脚本。
- `templates/`：七个条件各自的英文模板。
- `prompts/<condition>/1.txt` 至 `150.txt`：共 1,050 个 prompt。
- `indexes/<condition>.jsonl`：题目 ID、源比赛、原始 gold answer、prompt 路径、哈希、长度和通道计数。SHUFFLE 索引还逐题记录固定种子和排列。
- `CONDITIONS.md`：英文条件定义与解释边界。
- `validation_report.json`：源数据审计、对齐关系、条件不变量和复现检查。

在仓库根目录生成：

```powershell
python nba150/discussion_v3/build_conditions.py
```

仅验证现有产物，不写文件：

```powershell
python nba150/discussion_v3/build_conditions.py --check
```

脚本固定使用 UTF-8 无 BOM、LF 换行、源题目顺序和确定性的 SHUFFLE 种子。它不会读取 gold answer 来生成 prompt 或选择排列；删除或改变源 answer 字段不会改变任何 prompt。

## 条件与主要比较

- **FULL**：完整前后事件、真实比赛时间、完整比分与胜率轨迹。
- **TEXT_ONLY**：保留事件文本与真实时间，删除整个数值表，也不补比分或胜率摘要。FULL 与 TEXT_ONLY 比较数值轨迹的增量作用。
- **SERIES_ONLY**：保留完整四通道数值表、真实时间和目标行，删除事件上下文。FULL 与 SERIES_ONLY 比较事件文本的增量作用。
- **QA_ONLY**：只有通用题目、原始四选项和回答格式，用于观察选项本身的答题能力。
- **REMOVE**：同时移除事件记录、数值表和目标时刻中的显式比赛时钟，保留源顺序、Past/Future 分区和目标 Marker。没有添加序号或跨模态共享位置标签。
- **SHUFFLE**：目标事件以外的全部可见事件先获得固定种子生成的错排时间，再将事件、事件 ID 和新时间作为整体，按累计比赛秒数从小到大排序。数值表、表内真实时间、数值行顺序、目标 Marker 和 Target Moment 的真实目标时刻均与 FULL 完全一致；目标事件不参与排列。事件可以因重排跨越固定目标位置两侧的 Past/Future 分区。
- **RELATIVE**：事件与数值表统一改成距目标事件的精确相对秒数；目标为 0，之前为负，之后为正。真实间隔、源顺序及事件和数值的对应关系不变。

FULL 与 REMOVE/SHUFFLE/RELATIVE 是三种时间干预比较，但不是对三个理论概念的严格独立隔离。REMOVE 仍保留顺序、前后分区和自然语言中的阶段线索，例如 `End of the 4th Quarter`；这些信息仍可能帮助隐式对齐。SHUFFLE 的输出事件时间保持单调，但事件被重新分配到时间位置，因此事件与未改动数值表之间的对应关系发生冲突；Past/Future 分区仍给出相对目标的结构。RELATIVE 保留真实间隔，其相对跨度仍可能透露比赛进程，因此不能声称彻底消除了时间语义。

比分差可能让部分题无需复杂推理即可排除选项，这是后续应单独审计的证据捷径。未来观察在本任务中是溯因证据，可以帮助判断先前缺失事件；它不能被解释为过去事件的原因。

## 数据规则

全部数值直接取源 JSONL 并保留原始数字表示。`history[i]` 对应 `history_times[i]`；`future[0]` 是目标事件后的数值点，使用 `critical_moment.after.time`；`future[i+1]` 对应 `future_times[i]`。脚本逐通道检查长度并按索引取值，不使用会静默截断的 `zip`。

事件记录不再使用 v2 的 `Past 1`、`Future 1` 等位置标签，数值表也没有 Position 列。可引用事件使用稳定的不透明 ID；同一事件在各条件中 ID 相同，ID 不出现在数值表，也不显示时间、顺序或前后分区信息。REMOVE 仍可从上下排列看出事件顺序，但没有新增共享标签连接事件和数值行。

相对时间解析覆盖源数据实际出现的 `12:00-1st`、`57.0-1st`、`39.1-1st`、`OT` 和 `DO` 等格式。常规每节 12 分钟，加时每节 5 分钟；先由节次和剩余时间计算累计比赛秒数，再减目标累计秒数。计算使用 `Decimal`，不会引入二进制浮点尾差。节末与下一节开始可落在同一累计秒数，源顺序保持不变。未知格式会直接报错，不猜测或跳过。
