# NBA150 新版 FULL 输入讨论稿

本目录依据本次需求中已提供的 TSRBench NBA 溯因样例信息结构制作，用于团队讨论，**不声称逐字复刻官方原始 prompt**。任务是结合缺失位置之前和之后的事件记录及数值序列，选择中间最可能发生的事件；未来信息是本任务允许使用的证据。没有调用 GLM 或其他模型 API，没有启动评测。

## 文件与复现

- `full_template.txt`：英文可复用模板，使用 Python `string.Template` 占位符。
- `build_full_prompts.py`：仅依赖 Python 标准库的生成及验证脚本。
- `full/1.txt` 至 `full/150.txt`：全部 150 题的完整 FULL 输入，仅文本和数值表格。
- `index.jsonl`：源记录行号、题号、原始答案字母、事件及数值点数、每题 SHA-256、字符数和 UTF-8 字节数。答案标签只存于这个独立索引，不拼接到输入。
- `validation_report.json`：完整性、时间对齐、选项映射、数值精度、答案隔离及可重复性验证报告，并记录与摘要的差异。

在仓库根目录执行以下命令即可重新生成同一批文件：

```powershell
python nba150/discussion_v2/build_full_prompts.py
```

仅验证已生成文件，不写文件：

```powershell
python nba150/discussion_v2/build_full_prompts.py --check
```

脚本依据自身位置定位源数据，可从其他工作目录执行。不调用旧脚本，不读取或拼接旧版 `prompts/system.txt`；每个 FULL 文件自身包含篮球任务说明和回答格式。固定使用源文件顺序、UTF-8 无 BOM 和 LF 换行，不使用随机数或生成时间。重新生成仅更新本目录中的生成产物；原始数据、旧脚本、旧输入和实验结果不被覆盖。

## 新旧输入差别

旧版 `nba150/cli/full/` 只呈现历史事件、历史时间、历史比分及胜率，并加入 `critical_moment.before` 摘要；未来事件、未来时间和全部 future 数值数组均被删除。旧问题还使用“根据截至当前的信息判断最可能发生的事件”的措辞。新版明确询问中间缺失位置发生了什么，恢复全部未来事件及比赛时间，并提供独立数值表，覆盖完整历史、目标点和完整未来轨迹。

事件记录与数值表通过 `Past 1`、`Target`、`Future 1` 等位置标签和原始比赛时间对应；不截断、不抽样，不用省略号替代记录。旧脚本会将事件中的 `|` 改成 `/`，并将浮点数格式化到最多三位小数；新版保留事件原文、四个选项及顺序，并直接保留 JSON 中数值的原始表示，包括 `0.0`、尾随零和原有精度。没有添加球队花名册、答案推导提示或折线图。

回答格式统一为 `Answer: <A, B, C, or D>` 与 `Reason: <简短理由>`，不再要求旧版的置信度或证据索引字段。占位符不会填入正确答案；正常展示的四个选项中包含正确选项。

## 时间与数值对齐

四个数值通道分别是两队比分和两队胜率。每题先检查全部长度，再按下述关系逐项取值，不使用可能静默截断的 `zip`：

1. `history[i]` 对应 `context.history_times[i]` 和 `context.history_events[i]`。
2. `future[0]` 是缺失目标事件对应的数值点，时间取 `critical_moment.after.time`。此行只标为 `Target`，不填入目标事件描述。
3. `future[i + 1]` 对应 `context.future_times[i]` 和 `context.future_events[i]`。因此每个 future 数值数组都比未来事件数组多一个点。
4. 每题数值表行数为 `history 点数 + future 点数`，也就是 `历史事件数 + 1 + 未来事件数`。

全部 150 题共保留 32,098 条历史事件、16,286 条未来事件和 150 个目标点，合计 48,534 行数值、194,136 个数值单元格。第 10 题的未来事件数组为空，其 future 数值数组只有目标点；该题的 Future Events 显示 `None recorded.`，没有虚构后续事件。

验证也检查比赛时钟及节次顺序，并逐值比较历史末点与 `critical_moment.before`、future 首点与 `critical_moment.after`，以及历史末点时间与 before 时间。本批数据的 1,200 次数值摘要比较和 150 次 before 时间比较均无差异。若以后出现摘要差异，脚本会将差异写入报告，输入仍使用 `numerical_time_series` 原值，不以摘要覆盖。

数值数组本身没有独立时间戳，因此这里验证的是源数据给定的长度、顺序、时间边界、摘要和生成文件之间的一致性，没有另行访问比赛原始逐回合记录来证明数据采集层面的正确性。验证会重新解析全部落盘文件，逐条核对事件、数值、时间和选项；同时验证删除或改变源答案字母不会改变 prompt 的任何字节。

## 后续讨论

未来比分变化可能让部分选项容易排除，这是后续需要审计的证据捷径；本次不据此删除未来信息，也没有进行捷径得分测算或模型评测。

未来设计消融时，应区分 **NO_SERIES**（删除数值序列）与 **NO_TIMESTAMPS**（仅删除时间戳，保留数值序列）。旧版 `NO_TS` 实际只是删除时间戳。本次仅生成新版 FULL，没有批量扩展这些额外条件。
